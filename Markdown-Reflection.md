# Reflection on Coding in Markdown


## Situation

As part of the Project Presentation 3 assessment, I was required to create a professional digital portfolio using GitHub and Markdown instead of a traditional word processor. Although I had previously used GitHub to store programming projects, I had limited experience using Markdown to create well-structured documentation and professional portfolio content.
## Task

My objective was to convert my professional CV and portfolio content into Markdown while ensuring it was visually organised, easy to navigate, and suitable for publishing through GitHub Pages. I also wanted to understand why Markdown is widely used by software developers and how it contributes to professional documentation.

## Action

I researched GitHub Flavoured Markdown and learned how to use headings, lists, hyperlinks, horizontal rules, emphasis, and other formatting features to structure my content. I redesigned my CV specifically for the web instead of simply copying a Word document. Throughout the process, I regularly previewed my files on GitHub to verify that the formatting displayed correctly and made adjustments where necessary to improve readability and organisation.

## Result

Creating my portfolio in Markdown improved both my technical and documentation skills. I gained confidence in producing professional documentation using a format commonly used within the software development industry for README files, project documentation, and technical guides. This experience demonstrated that effective software development involves not only writing code but also communicating information clearly and professionally. I now feel more prepared to document future software projects using industry-standard practices.
